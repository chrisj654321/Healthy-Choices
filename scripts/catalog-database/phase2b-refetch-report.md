# Phase 2b — OpenFoodFacts re-fetch report

Generated by a one-off review pass over the 64 barcodes in
`scripts/catalog-database/phase2-refetch-list.md`. For every barcode, the
verbatim `ingredients_text_en` (falling back to `ingredients_text`) was
fetched from `world.openfoodfacts.org/api/v2/product/<barcode>.json`, run
through `normalizeIngredientTokens()`, and compared token-by-token — using
the SAME runtime classifier `analyzeIngredients()` uses in
`src/utils/scorer.js` (`lookupIngredient` + `classifyTokenPlausibility` +
`isLabelBoilerplate`) — against what is already stored, to see which
tokens would actually be HIDDEN (garbage, invisible on the product screen)
vs SHOWN to a user, before deciding to touch anything.

`src/data/products.js` was changed for 12 barcodes (targeted per-product
splice, byte-identical everywhere else — verified by re-parsing
`MANUAL_PRODUCTS` and diffing every untouched product). `assets/db/products.db`
was rebuilt from the updated source. 3 barcodes need further manual work
(see `phase2-manual-needed.md`). The remaining 49 were confirmed
false-positives or had no usable improvement available and were left
untouched.

## Summary

- Re-fetched and applied: 12
- Left unchanged — false positive (current ingredients are already real,
  not OCR/packaging garbage; the >6-word / digit-in-word / "100%" heuristics
  in the classifier over-flagged them): 49
- Left unchanged — no usable OFF data (manual re-entry needed): 3
  (see `phase2-manual-needed.md`)

Note on the two manual extractions (Lipton, Philadelphia): a plain
`normalizeIngredientTokens(rawOffText)` call on the FULL fetched text
actually made both of these WORSE, not better — `truncateAtLabelSections()`
cuts the text at the first nutrition-facts marker it finds, and in both of
these specific OCR scans the nutrition panel appears BEFORE the real
ingredient declaration (label photo order), so the auto-truncation throws
away the real ingredients and keeps only nutrition-panel noise. Confirmed
this with a direct test before deciding to hand-extract the ingredient
substring for these two. The same issue was found (and is why the fix was
NOT applied) for Frosted Strawberry Pop Tarts (`0038000223006`) and Eggo
waffles (`0038000940644`) — Spanish/bilingual nutrition-panel fragments
became MORE visible after a naive re-fetch, not less, so both were left
unchanged.

## Notable false-positive families left untouched (of the 49)

- **"riboflavin {vitamin b2}" family** (Ritz × 5 duplicate barcodes, OREO
  mini, Oreo, 2× Kraft Heinz wheat crackers): the classifier's
  digit-in-word check flags any vitamin code ("b2", "b6", "b12") as
  mangled OCR. This is a documented, accepted false-positive in
  `ingredientNormalizer.js`'s own calibration notes. Current text is a
  real (if unsplit/compound) ingredient declaration.
- **"100%\_\_\_" family** (Tropicana, Simply Orange, Nescafé, Kodiak ×2,
  Eggo/Blueberry Waffles ×2, Jif, 6× coffee brands, Classic Roast): the
  nutrition-vocab regex flags any "100%"/"2%" as a nutrition-facts
  fragment even when it is a real ingredient qualifier ("100% whole grain
  wheat flour", "2% leavening", "100% arabica coffee").
- **">6-word real descriptor" family** (BodyArmor, Kashi — both named in
  the brief as known false positives; also Pirate's Booty, Gerber Puffs,
  Barilla, Eden Foods, Swanson broth ×2, Jimmy Dean ×2, Twinings): a real,
  if long, ingredient disclosure phrase ("expeller pressed canola oil
  and/or sunflower oil and/or corn oil", "natural lemon flavouring with
  other natural flavourings").
- **OFF data equal-or-worse than current** (STONEGROUND WHEAT CRACKERS —
  OFF's field is truncated mid-list and would have dropped 6 real
  ingredients; Concord Grape Jelly, LUNCHABLES HAM & CHEDDAR, Lunchables
  Extra Cheesy Pizza — OFF's re-scan introduces literal newline characters
  inside tokens, new typos, or hides a real ingredient that was
  previously visible).
- **Current already fully clean, OFF only offers more granular splitting**
  (Campbell's Chunky Sirloin Burger Soup, Honey Roasted Cereal, Honey
  Bunches of Oats Vanilla, Cocoa Pebbles, Frosted Strawberry (non-Spanish
  variant)): 0 visibly-garbage tokens in the current data already; OFF's
  version just breaks compound disclosures into more atomic tokens, which
  is a tokenization-granularity improvement, not a garbage fix, so it was
  left out of scope for this pass.
